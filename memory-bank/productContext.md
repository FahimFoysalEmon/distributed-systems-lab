# Product context

This is a **personal learning lab**, not a product. The “user” is the learner who wants to understand how distributed systems pieces work end-to-end.

## Why it exists

Reading system-design posts is not enough. Implementing consistent hashing, Kafka flows, caches, etc. makes failure modes and trade-offs concrete.

## How it should feel

- Start the app, hit an endpoint or run a test, see the concept behave.
- Short notes next to code: problem → approach → trade-offs.
- Add infrastructure (Docker, Kafka) only when the topic needs it.
